# FreeISP brain board — KiCad project

Single-layer 100 × 100 mm carrier for the ESP32 and everything that lives with
it inside the module. Generated by `build.py`, verified with KiCad's own DRC.

Open `freeisp_brain.kicad_pcb` in KiCad 10 (PCB Editor). There is no schematic —
nets are declared in the board file, so the ratsnest and DRC work without one.

| | |
|---|---|
| Board | 100 × 100 mm, 1.6 mm FR-4 |
| Copper | **one layer** (`F.Cu`). `B.Cu` is declared only because KiCad's minimum is two — nothing is routed on it |
| Clearance | 0.6 mm |
| Track width | 0.6 mm signal · 1.5 mm power · 2.5 mm available for the 12 V horn run |
| Pads | 1.9 mm on 2.54 mm pitch · 2.4 mm on terminals · 2.2 mm on resistors |
| Mounting | 4 × M3 Ø3.2, 4.5 mm in from each corner |
| DRC | **0 errors**, 38 unconnected (the unrouted signals) |

## What is already done

Placement, all 27 nets, board outline, mounting holes, the perimeter ground
ring, its stubs to every ground pin, and the fused 12 V hops across the top row.

## What you do

1. Open the board. The blue ratsnest lines are the 24 signal connections left
   to route.
2. Route on **F.Cu only**. Where a trace genuinely cannot get through, place a
   wire link — a track on `B.Cu` between two pads, fitted as a real wire on the
   component side. Expect six to ten.
3. `GPIO33` (TFT backlight) sits on the left row but J4 is on the right, so
   that one needs a link no matter how you route it.
4. Run DRC until it is clean.
5. Plot **F.Cu mirrored** for toner transfer — copper goes on the bottom,
   components on top.

## Warnings you can ignore

`lib_footprint_issues` × 26 — pads were deliberately enlarged from the library
defaults so hand-drilled holes still land on copper. `silk_overlap` × 5 —
reference designators touching; drag them if it bothers you.

## ⚠ Check before you etch

The ESP32 pin map in `build.py` (`U3A_NETS` / `U3B_NETS`) is the standard 30-pin
DevKit V1 order. **Clone boards shuffle their headers.** Read the silkscreen on
your actual board and correct the map if it differs — this is the one mistake
that costs you the whole etch.

## Regenerating

```
python build.py
"F:\kicad\bin\kicad-cli.exe" pcb drc --format json --output drc.json freeisp_brain.kicad_pcb
"F:\kicad\bin\kicad-cli.exe" pcb render --output board.png --side top freeisp_brain.kicad_pcb
```

`build.py` **overwrites** the board file, so any routing done in KiCad is lost.
Once you start routing interactively, stop regenerating — or move placement
changes into `build.py` first and re-route after.
