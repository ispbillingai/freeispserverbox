# FreeISP brain board — KiCad project

Two-layer 100 × 100 mm carrier for the ESP32 and everything that lives with it
inside the module. Generated by `build.py`, routed by `router.py`, verified
with KiCad's own DRC.

Open `freeisp_brain.kicad_pcb` in KiCad 10 (PCB Editor). There is no schematic —
nets are declared in the board file, so the ratsnest and DRC work without one.

| | |
|---|---|
| Board | 100 × 100 mm, 1.6 mm FR-4, 2 layers |
| Clearance | 0.25 mm |
| Track width | 0.4 mm signal · 0.8–1.2 mm power |
| Vias | 17, Ø0.8 mm with 0.4 mm drill |
| Mounting | 4 × M3 Ø3.2, 4.5 mm in from each corner |
| DRC | **0 errors, 0 unconnected** |

## It is fully routed

`router.py` is a grid maze router. Obstacles are inflated by
`my_half + clearance + their_half` and any cell whose centre falls inside is
blocked, so KiCad's DRC agrees with it. The search runs over
`(cell, layer, heading)` with a turn penalty and a via penalty. Three orderings
are tried — power-first, shortest-first, longest-first — and whichever needs
fewest vias wins.

Every pad is through-hole, so a path may begin and end on either layer without
a via; a via on top of a pad would be redundant copper.

## ⚠ Nothing gets ordered until the paper test passes

**DRC does not check that a footprint matches a real part.** It checks
geometry. A board can be perfectly clean and still have the wrong number of
pins on a connector — that has already happened once here.

`fitcheck_1to1.pdf` is plotted at exact 1:1 scale.

1. Print it with scaling **off** (not "fit to page").
2. Measure the board outline — it must be exactly 100 × 100 mm. If it isn't,
   the printer scaled it and nothing else on the page is trustworthy.
3. Sit the **real ESP32, TFT, RC522 and MPU-6050** on their outlines. Every
   pin must land on its hole.
4. Check the terminal blocks and resistors the same way.

The ESP32 socket assumes **25.4 mm between the two pin rows** and a **30-pin**
board. Some clones use 22.86 mm, and 38-pin variants exist. This is the single
most expensive thing to get wrong.

## Modules that are wired, not plugged

The **LM2596 buck** and **TP4056 charger** have edge pads meant for wires, not
0.1″ headers. They bolt alongside the board and land on 4-way screw terminals:

- `U1` BUCK — IN+ · IN− · OUT+ · OUT−
- `U2` CHARGER — IN+ · IN− · B+ · B−

The 12 V feed is fused **inline in the wire**, not on the board.

## Still open

- **Backup power is not solved.** The TP4056 outputs battery voltage
  (3.0–4.2 V), not 5 V, and has no automatic switchover. Running the box off
  the 18650 when mains dies needs a boost converter that is not on this board
  yet. The 12 V horn needs its own answer — a thief cutting power is exactly
  when the alarm must still sound.
- ESP32 pin map in `build.py` (`U3A_NETS` / `U3B_NETS`) is the standard 30-pin
  DevKit V1 order. Verify against your board's silkscreen.

## Warnings you can ignore

`lib_footprint_issues` × 23 — the embedded footprints have their library
version metadata stripped, so KiCad cannot match them to the library.
`silk_overlap` — reference designators touching; drag them if it bothers you.

## Regenerating

```
python build.py
"F:\kicad\bin\kicad-cli.exe" pcb drc --format json --output drc.json freeisp_brain.kicad_pcb
"F:\kicad\bin\kicad-cli.exe" pcb render --output board.png --side top freeisp_brain.kicad_pcb
"F:\kicad\bin\kicad-cli.exe" pcb export pdf --mode-single --output fitcheck_1to1.pdf --layers "F.Cu,F.SilkS,Edge.Cuts" --scale 1 --black-and-white freeisp_brain.kicad_pcb
```

`build.py` **overwrites** the board file. Once you edit anything in KiCad, stop
regenerating — or move the change into `build.py` first.
